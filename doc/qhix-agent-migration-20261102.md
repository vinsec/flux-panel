# qhix 统一 Agent / 原生 nftables 迁移验收

2026-11-02，qhix（逻辑节点 ID 1）已升级到统一 Agent 并实际切到原生 nftables。面板、实时 Agent 和持久化状态均为 `forwardingMode=kernel`，`kernelBackend=nftables`。qcloud 同样保持原生模式在线，本次没有修改其节点配置、二进制或服务。

## 最终状态和账本

- 原 17 条规则全部启用并应用，17 条协议识别就绪；14 条普通用户规则的有限额度有效并持续续租。最终复核最小、最大续租代数均为 57，无 lost lease。
- 原入口 IP、TCP/UDP 端口、目标、规则 ID、用户授权及配额保留。入口仍为 `163.223.124.231`；实际出口 SNAT 为 `209.248.1.45`，保持原 GOST 的默认出站地址。
- HTTP/TLS/SOCKS 三个屏蔽开关均保留为开启。无法可靠识别的流量放行并标记 UNKNOWN。
- 业务由原生 DNAT map 执行，受管 GOST 的业务服务数为 0；旧 `gost.service` 已停止、禁用，旧程序、配置和 device.id 哈希未变。受管 GOST 空进程保留以支持后续模式切换。
- `flux-agent.service` 和 `flux-kernel.service` 均启用、运行，最终 PID 为 53478 / 53476，自动重启次数均为 0。网络进程 capabilities 为 0；helper 仅保留 NET_ADMIN、NET_RAW、NET_BIND_SERVICE，没有长期 SYS_ADMIN 或 SETUID。
- 历史数据库账本未重置、未恢复整库快照。原规则累计值不倒退，新 epoch 只上报迁移后的增量。最终 Agent 修复重启后 epoch、boot 身份和累计计数保持连续；状态格式为 8。
- 临时入口保护表已删除，本地端口保留设置已恢复；两侧迁移均已提交，临时回滚定时器取消。

## 实际中断、失败与修复

第一轮因 qhix 的 nft 1.0.6 无法接受超过 uint32 范围的单段毫秒 timeout，17 条规则批次未落地，约 80 秒后回滚到旧 GOST。此轮没有有效新规则、流量或 credit，空启动状态单独归档。实际用户授权包括超过 49.7 天的期限，隔离复现后改为等值的天/时/分/秒/毫秒组合格式，未缩短授权期限。

同时修复了原生注册握手把面板 HTTP/TLS/SOCKS 策略覆盖成 0 的问题：只有旧 GOST 使用握手同步这些标志，原生 Agent 保留面板策略。Oracle 只替换兼容修复后的后端，镜像为 `oracle/panel-go:qhix-compat-20261102-arm64`；前端仍为 cfabd1f，其他服务未重启。后端重启带来控制连接重连，不能表述为整个过程中面板从未重启。

第二轮入口保护窗口约 **19.5 秒**，17 条规则和 14 条初始额度就绪后放开入口。但随后发现闲置规则的零消费确认被统计分页遗漏，普通用户额度在初次到期后未续租。因此 **19.5 秒只是入口切换窗口，不代表普通用户总受影响时间**；管理员规则在该问题期间仍有自然双向业务。

已通过现有鉴权上报和 helper credit IPC 热恢复 14 条额度，没有编辑账本状态文件或清空原生数据面。产品修复允许首次闲置额度确认独立于脏流量分页，避免后续续租停滞。随后部署修复版，helper/网络服务重启恢复约 **6.6 秒**，epoch、boot 身份和累计值均未改变。普通用户额度已跨多个周期自动续租，并在最终复核达到第 57 代。不能把迁移描述成全程无中断或仅中断 20 秒。

源码修复在 main：`a7af470`（长期限、策略保留及协调日志/重试），`762bf10`（闲置额度确认）。qhix 最终 Agent SHA256：`8cd3b8e066d6270cd3300292407dcd7ccbdc6dbdb494d1c891842df87aa8daa1`。qcloud 的 Agent 未随本轮替换；其现有三条管理员规则没有本轮有限额度续租路径。

## 验证范围

- qhix 实际内核的隔离网络命名空间：统一 Agent/受管 GOST 切换 18/18、协议屏蔽 29/29，通过 TCP/UDP、暂停恢复、计数、有限配额、UNKNOWN、分段前缀、私有 IPv6、本机 OUTPUT、故障恢复等检查。测试网络没有外部路由。
- 17 条真实规模规则的隔离重放通过，含长授权期限和 14 条有限额度；4 秒短额度连续 8 个采样周期均有 14 条有效额度，最小代数连续从 3 增至 10。
- 真实 systemd 缩权配置使用独立空配置验证子进程启动，没有注册线上节点身份。
- Agent `go test -race ./...`、`go vet ./...` 通过；面板使用独立临时 MySQL 的 race 全套及 vet 通过。临时测试数据库容器已清理。
- 线上只读取状态并被动观察自然业务。管理员规则 34/35 双向字节持续增长，出现原生 TCP 已建立和 UDP ASSURED 记录。没有生成 GZ 或其他公网测速、压测、业务回声；闲置规则的就绪状态与隔离验证不等于对所有 17 个公网入口逐一完成端到端测试。
- 本轮没有新增吞吐、CPU、延迟基准数据，不能据此宣称性能提升；此处验收的是部署、隔离功能回归、账本与实际模式。

## 备份和回滚边界

qhix root 私有目录 `/root/flux-agent-migration-20261102/` 保留旧 GOST、systemd、配置、device.id、操作记录及修复前状态；Oracle `/app/flux-agent-qhix-migration/20261102/` 保留数据库、原部署和节点元数据备份。敏感配置及整库备份不进入仓库。

自动回滚脚本在 COMMITTED 后拒绝执行。若后续回到旧独立 GOST，需要重新核对新增规则、策略与账本，结算原生增量后安排短窗口；不能直接恢复旧整库或删除提交标志来强制回滚。统一 Agent 内的受管 GOST 切换与退回旧独立服务是不同操作，均需保留当前计数。

配套 [脱敏机器记录](qhix-agent-migration-20261102.json) 保留计数、测试及部署摘要，不含密钥、用户明细或客户端地址。
