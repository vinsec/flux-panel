# P1：双栈、域名、选路、限速和权限隔离

代码基线为 P0 `32a2ebb`，P1 核心代码为 `0731178`。本文件说明实际实现与边界；验收结果另见 `forward-p1-validation.md`。本轮不执行生产迁移、不发布 GitHub Release，也不部署节点。原 29 项编号继续沿用。

## 数据模型与兼容

原 GOST 适配器继续使用既有协议。简单 IPv4 TCP+UDP、单目标、无限速的 iptables 业务保留原 C7 哈希路径和 JSON 形状。高级请求使用 schema 3：独立 listeners、带权 targets、DNS/健康策略、出口和带宽；持久化格式为 4。配置版本 revision 与节点解析 generation 分开。运行时 IP、健康、mark、命令文本均不是远端可写字段。

服务仍只有一个业务 ID、token 和累计账本；双地址族或多个目标不会复制用户额度。高级路径用 F2 标记与 FP4/FP6 独立资源，原 F1 路径保留。每族每包分类、放行和业务计数使用 ipset 哈希；DNAT 首包经过固定深度 token 树，单目标直接进入树叶，目标池最多 16 个来源、权重和不超过 32。普通报文不会扫描全局转发表。

支持同族 IPv4→IPv4、IPv6→IPv6及双栈入口。跨族、OUTPUT/hairpin、本机目标、带 zone 的 link-local 目标仍拒绝；没有借此宣称支持 NAT64 或 Happy Eyeballs。网关可由显式出口接口确定链路范围。Agent 不自行修改主机 forwarding/RA 等 sysctl。

## 域名与健康

DNS 由节点查询，支持 A/AAAA、CNAME、RR TTL、UDP 截断后的 TCP 回退、NXDOMAIN/NODATA 与临时失败。每个来源/地址族保留一个稳定数字地址，刷新采用 TTL 80–90% 的抖动；TTL=0 不长期缓存。默认临时失败宽限 30 秒，可立即关闭；NXDOMAIN/NODATA 不使用 stale。独立到期检查保证 DNS worker 超时或容量不足不会无限续用旧地址。

刷新先准备新目标，切换新连接；已确认 conntrack 保持旧映射，仍受同一暂停和配额控制。旧目标默认最多排空 5 分钟，可配 1 秒至 1 小时。排空期限后连接可能中断，这是有界资源策略。用户显式修改目标/监听/出口采用定向清理已有连接，不承诺无损模式迁移。

后台调度每轮最多 8 个业务、4 个 worker，每个业务 DNS/健康工作有 4 秒上限，DNS 查询全局最多 16 个；健康每次最多探测 4 个目标，按最早到期优先。大量短 TTL 独立域名不保证全部及时刷新，超过 freshness/stale 期限即关闭新连接并显示失败。10k 数字目标容量不能解释为 10k 短 TTL 域名的刷新吞吐保证。

首包支持首个可用、源 IP 稳定哈希、加权轮询、加权随机；conntrack 保持既有连接。健康检查有超时、rise/fall；UDP 必须配置最多 64 字节的显式请求和期望响应，不能把 UDP connect 成功当可用。所有目标探测失败会显示失败，尚未完成探测则显示等待。

## 额度、计数与暂停

双栈共享硬额度使用同 netns 的原生 nft named quota 对象、mark 映射和独立期限集合，避免 IPv4/IPv6 各拿一份 budget。事务屏障优先于 quota，DNS 更新只挡未确认连接。TTL-only 续租保留原 quota 对象和已消耗值；重启、重放不能重新获得完整预算。

因此高级 iptables 模式需要 nft CLI/内核额度原语；这不是第 27 项完整 nftables 转发后端。数据转发仍使用 iptables/ip6tables 和 ipset。其他防火墙在额度 gate 之后丢弃时，可保守预消耗内核额度；最终业务结算仍以业务累计计数为准，不把此情况承诺为可用额度无损。

计数基线按集合/地址族分开，业务报告汇总到同一 ID。面板接受 FPV2、FP4、FP6 的上下行水位；每个水位不能超过对应方向累计值。缺失/回退保护、ACK 后 GC、中央短期 credit、离线到期沿用 P0。维护最终结算超过 10k 个业务时分页，保留累计水位。突然断电未落盘字节的损失边界仍沿用 P0，不能保证零损失。

## 出口、动态地址和整形

出口仅使用专属策略表与 F2 原方向标记，最多 63 种不同出口策略，不改主默认路由。源地址必须属于所选接口。软件 capability 与主机条件分开，具体地址、模块和 forwarding 仍需通过节点预检/应用验证。替换前检查表和引用规则的实际所有权；即使落在保留表号范围，也不覆盖外来资源。接口/源地址失效只关闭相关业务；地址恢复后重建。netlink 驱动通配绑定更新；IPv6 tentative/DAD failed 地址不加入，暂停不会被地址事件恢复。

可选 HTB/fq_codel 使用有所有权 alias 的 IFB，物理网卡保留原 root qdisc；仅安装明确拥有的 clsact/fw 分类器。上/下行分别整形。层级沿用面板业务：用户总带宽→用户隧道授权 UserTunnel→单转发；不是新增跨用户的全局隧道配额。只有管理员能设置共享上限，普通用户只能收紧单转发上限。

HTB 保证速率按层级自上而下分配，所有子级保证值之和不超过父级；独立上限放在 ceil，避免两个转发把共享上限相加。最小可表示保证为每子级 8 bit/s，无法表示的超小总上限/超多子级组合明确拒绝。暂停删除叶队列和分类器。接口同名重建时依据实际分类器存在性重新安装，不能仅相信旧 manifest。

## 监控、表单与安全

CPU、内存、网卡、uptime、conntrack 读取真实 /proc，网卡速率用采样差值；首次、重置或不可用值为 null。界面用缺失状态展示，不伪造 0。管理页读取实时回执和容量，转发页展示节点真实生效版本、解析代次与失败原因。诊断限定已存转发，最多每族一次 500ms TCP 握手，UDP 要求配置明确交换；不自动运行吞吐测试。

网页按能力展示双栈、域名、监听、权重、出口和限速，GOST 表单保留原路径。Android/iOS 当前为网页容器，复用网页功能；本轮响应式网页验收不能解释为已产出新的原生安装包。

新 Agent 默认把认证放请求头；旧 URL 方式必须显式 legacyQueryAuth。可启用短期 opaque session，面板只存哈希，按相对有效期/单调时间轮换；吊销关闭当前会话，新会话重新用 bootstrap 认证。bootstrap 仍是节点长期凭据及 AES 密钥来源，本轮没有自动轮换它。浏览器监控使用一次性 30 秒 ticket。旧 GOST 的兼容 URL 认证可以在迁移后由管理员统一关闭。

systemd 把网络进程放到专用用户、零 capabilities；root helper 只保留 NET_ADMIN/NET_RAW/NET_BIND_SERVICE，经受保护 AF_UNIX socket 和 peer UID 校验提供类型化 allowlist。helper 不提供 shell、任意命令或任意规则文本 RPC。配置 root 0600，网络进程通过 LoadCredential 获取。日志副本统一脱敏；不会为旧 GOST 二进制自身的日志提供新 Agent 的脱敏保证。

## 安装与回滚

显式执行迁移 `003-engine-p1.sql`，此前先完成 001/002。新发布包固定 manifest/installer SHA，包含两个服务单元；安装失败先停止新网络进程/helper，再由维护工具回滚，避免锁被仍在运行的 helper 持有。备份包含 IPv4/IPv6 规则、共享额度、路由、整形和累计账本。

维护/回滚会暂停业务，保持最新累计账本，不自动恢复旧连接。回退到旧版本恢复其支持的配置快照，不把旧 Agent 不支持的新选项强行转换成可运行规则。灰度、生产库迁移和真实公网入口验证仍属于原第 10 项，另行执行。
