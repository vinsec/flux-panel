# v5.5 统计/账本与冷连接验证

在 v5.4 基础上优化 counter 身份/排序、checkpoint 规则编码和空 TCP ACK 路径。已实现机制见 [说明](forward-performance-v55.md)。仅本地源码与隔离测试，未登录或修改线上节点、面板或数据库，没有走 GZ/公网转发入口。

开启同样的协议屏蔽，新连接完成速率较 v5.4：原生 nft **5.5%**，保留 iptables **7.0%**。仍有用户态首包判定成本，不承诺达到关闭识别的上限；持续连接已分类后走内核。新连接主结论来自每组连续10万次、20个独立源IP的测试，跨越多个1Hz采样周期。最初5000次短突发有明显相位偏差，初测约30%的提升没有稳定复现，未作为结论。表内数值为三轮轮换顺序中位数，原始 min/max 和每个样本在 [JSON](forward-performance-v55-validation.json)，没有将微基准或单轮峰值当作吞吐提升。

持续 TCP 的 p50 在原生 nft 样本中为62.2→71.1µs，保留后端为71.4→73.2µs；连续新连接 p50 则略有降低。虚拟机的调度/唤醒与统计相位存在波动，未据此宣称所有延迟指标改善，也不承诺微秒级绝对零回退。

统计 CPU 指标包含收发端和软中断，不等于仅 Agent；单列 Agent CPU 与独立软件 profile 见 JSON。短窗口每向 8GiB 并核对完整收包回执，保留后端另做每窗 64GiB 的三轮上行复测，降低 1Hz 统计相位影响。全部延迟探测丢包为零，定速150Mbps通过。核心 iptables 转发规则在三种构建配置中摘要一致，变化位于识别及采样/编码路径。

## 功能及一致性

最终构建通过 61 个 Linux 引擎单元测试、21 组真实内核/升级黑盒、390 次断言；Go 全模块竞态检测与 vet 通过，ARM64/AMD64 交叉构建完成。包含协议独立开关、UNKNOWN、TCP/UDP 配额与字节计数、暂停、IPv6/OUTPUT、SYN-data、乱序前缀、万规则增删/分页/GC、元数据丢失、事务各阶段失败、重启恢复、旧版读写互通和最小权限 helper。实际入队计数确认串行普通新连接为 SYN+首数据两次，空 ACK 及后续缓存数据不入队。

规则缓存只复用由 JSON 编码器产生的可信字节；同一 checkpoint 解码值必须等于当前完整 State。所有状态替换、回滚和运行时规则更新失效缓存。没有合并/延迟持久化，没有提前 ACK，格式与 fsync/rename/目录同步保持原样。旧版→新版→旧版→新版的接管测试保留 epoch 和单调账本。

独立微基准（不含磁盘和 NFQUEUE syscall）：万规则编码约17.3ms→2.5ms。早期 RawMessage 方案重复验证 JSON，耗时约25ms，已舍弃。不能把约85%编码耗时降低当作端到端CPU或吞吐同比改善。

软件CPU采样中，旧版292个样本、新版216个样本；Report调用树占比76.7%→72.2%，JSON Marshal占比26.7%→14.4%。这些是含子调用的比例，不可相加，也不将样本数下降直接当作精确CPU百分比。采样/编码仍是主要剩余控制面成本。
