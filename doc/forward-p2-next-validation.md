# P2 第二批验证：本地平滑限速与 UDP 源地址

2026-10-28，基于 `c013febf`，Agent `iptables-v5.1`。数据与哈希见
[验证摘要 JSON](forward-p2-next-validation.json)，功能、前置条件及剩余任务见

## 环境与功能

Fusion Debian 13 ARM64，Linux `6.12.113+deb13-arm64`，4 vCPU / 4GiB，
iproute2 6.15.0 / libbpf 1.5.0。每个测试新建 mount/net namespace，业务只在
私有 veth/回环传输，路由检查禁止外部出口；没有经过 qcloud GZ。

- 24 个功能套件、758 次断言执行全部通过：iptables-nft/legacy，各含 root、
  可选 helper、基础 helper 缺少 BPF 权限、P1/P2 回归与九个崩溃点。
- 本机/物理来源、远端/本机/回环目标、双栈 TCP/UDP、共享用户带宽、暂停、
  8KiB 双向配额、确定性网络字节计数、重启与所有权清理均有真实 socket 验证。
- 固定绑定 UDP 服务观察到实际来源；绑定改成通配时关闭、恢复后收敛。
  本机大 UDP 通过 IPv4 65507 / IPv6 65527 字节验证。
- 指定出口/源地址与本地限速组合通过，TCP/UDP 连续传输验证每方向只入队一次；
  中间路由器实际生成的 IPv4 fragmentation-needed / IPv6 Packet Too Big 能返回。
- 删除 IFB 后重建；物理 IPv6 地址 DAD、增加、删除保持正常；外部 classifier
  保持不变。无 capability 网络进程与可选 helper 分别验证。
- Linux 原生 engine 单元检查 39 项；Go race、Linux vet、前端构建通过。
  Maven 18 项通过、1 项因原有环境条件跳过。
- 另一隔离 Linux 6.1 环境运行真实 Spring Boot/MySQL，通过 60 项检查，包括
  10k 批量应用、9998 孤儿清理、额度续期、GOST 兼容和强制删除/对账竞争。

回归修正了 IFB 自身通知引起的重复停流重建，并避免用新接口清单跳过旧绑定
快照而漏掉 IPv6 删除。还修正限速对账读取旧 DB 快照、随后用新 revision 复活
删除规则的竞争：复用物理节点变更锁，覆盖期望快照及交互操作最后 DB 写入。
恢复的首笔额度仍在事务提交后发放。

## 未启用新能力的性能回归

冻结 v5 与候选 v5.1 在同一 VM 交错三轮；3/10000 条规则，每方向连续
8 次 1GiB 接收确认，150Mbps/20秒 CPU，TCP/UDP 各 5000 次常驻 RTT。
共 196.19GiB **隔离内网应用负载**，120000 次 RTT 无丢失。
每次启动校验实际 `/proc/PID/exe` SHA。两种规模的可达转发规则图与自有集合
完全相同；没有为未使用的本地功能加载 BPF/入口分类器或增加 P2 集合。

下表为三轮中位数的候选相对冻结版变化；CPU 为整个 guest cgroup，包含端点。

| 规则数 | 上传吞吐 | 下载吞吐 | 固定速率 CPU | TCP p95 | UDP p95 |
|---|---:|---:|---:|---:|---:|
| 3 | +1.03% | +1.64% | +11.91% | +44.0μs | +1.0μs |
| 10000 | -0.99% | +0.52% | +2.21% | -0.4μs | +4.4μs |

3 条规则 CPU 首轮高约 0.76 个单核百分点，追加三轮交错、40秒/150Mbps
确认，先清除 TCP metrics 缓存：CPU/GiB 中位数由 4.294 到 3.922 秒（-8.67%），
Agent CPU 每窗口约 0.19–0.21 秒、两版基本相同。初轮与确认方向不稳定，
不把它解释为 CPU 改善或稳定退化。3 条规则 TCP p95 的轮次范围重叠
（旧 235–258μs，新 220–293μs），仍保留 +44μs 的原始观察。

因此本轮未确认基础数据路径存在系统性退化，不能据此承诺每个分位数零变化。
所有吞吐为 VM 内虚拟网络结果，不是公网/物理 NIC 带宽；CPU 不是独占物理 PMU
归因。原始样本和确认数据分别保留，不混成一个窗口。

## 启用新限速的实际成本

本地到本地，200Mbps 共享上限下固定发送 150Mbps；与同版不限速配置做
两轮反向顺序对照，每次 20秒，负载期间各取 2000 个 TCP/UDP RTT。

| v5.1 配置 | 实际接收 | CPU1 占用 | TCP p95 | UDP p95 |
|---|---:|---:|---:|---:|
| 不限速 | 150.00Mbps | 6.98% | 113.0μs | 140.8μs |
| 共享限速 200Mbps | 149.98Mbps | 8.31% | 112.9μs | 144.3μs |

新队列增加约 **1.33 个单核 CPU 百分点**；这是限速/ct/BPF 的功能成本。
CPU1 含主负载端点和 softirq，RTT 服务调度也受 VM 影响，不作为物理机精确归因。
8Mbps 实际限速、共享聚合、UDP 持续回显、暂停与配额另由功能测试验收。

## 约束与产物

本地限速需管理员准备回环 MTU/sysctl、bpffs，以及可选 helper 的 CAP_BPF +
CAP_SYS_ADMIN 配置；默认 helper 权限不变。当前 stock tc/libbpf 的模块 BTF
接口有此权限需求，后续缩权加载器仍待实现。UDP 源地址保留只承诺固定绑定
目标 IP 并用该 socket 回复的服务；通配/IP_PKTINFO 契约、额外 IPv6 回环、
原始本机分片组合及其他 P2 仍按实现说明保留。
