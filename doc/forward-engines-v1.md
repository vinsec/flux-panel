# 可选转发引擎：实验版 v1

本分支保留 GOST 为默认引擎，新增独立的 iptables 节点。节点创建时指定引擎，隧道选择与入口节点匹配的引擎，其下的转发继承该模式。已有记录迁移后默认为 GOST；已创建节点/隧道不允许原地修改引擎，应通过新节点、隧道迁移。

## 代码结构

- `common/engine/ForwardingEngine` 定义转发创建/更新、启停和删除接口。
- `GostForwardingEngine` 调用保留的 `LegacyGostCommands`；旧命令构造代码仅更改类名，保持原有 GOST 格式。
- `IptablesForwardingEngine` 发送中立的单目标 IPv4 转发请求。
- `GostUtil` 作为兼容入口分派引擎，使原有用户、配额、到期、清理等生命周期调用也经过同一适配层。
- 独立 `node-agent/` Go module 使用 WSS 控制和 HTTPS 统计，无 GOST 模块依赖。业务数据由 Linux 内核转发，不经 Agent 搬运。
- `EngineReconciler` 查询节点状态，恢复缺失配置、同步状态并清理孤立规则。

## 数据与计费

显式迁移脚本：`springboot-backend/migrations/001-forward-engines.sql`。它增加 node/tunnel 的 `engine` 字段及持久化命令版本、统计水位表。迁移脚本不在应用启动时自动执行。

iptables 的原始字节来自 FORWARD，包含网络层开销和重传，不等同于 GOST 的用户态读写字节。两种模式保持原面板的流量倍率和单/双向计费系数（×1 / ×2），界面说明两种原始计量口径不同。

新统计以 epoch、序号和累计字节上报，数据库事务中去重并更新转发、用户、用户隧道账本。删除前结算最后采样。Agent 保留本地账本和计数基线，状态丢失而内核规则/计数仍存在时拒绝重置 epoch，避免历史流量重复入账。

本地到期控制独立于统计 HTTP 请求执行，面板失联时已知到期时间仍生效。共享用户配额仍依赖面板的采样和暂停回执，不能保证断线期间跨节点精确硬配额。

## 首版边界

- 支持外部入站的单目标 IPv4 TCP/UDP 端口转发，两种协议使用相同监听地址和端口。
- 支持创建、更新、暂停、恢复、删除、持久化恢复和配置对账。
- 暂不支持目标为本机/回环地址、本机 OUTPUT、hairpin NAT、IPv6、跨地址族、域名目标、多目标、GOST relay 隧道封装、平滑限速和应用协议屏蔽。
- 同物理机的 GOST/iptables 逻辑节点使用独立身份、相同 `serverIp` 和不重叠端口；面板进行保守的跨引擎端口预留，Agent 另行检查本机监听端口。
- 系统 CPU/内存/网卡监控尚未实现，iptables 节点界面显示为未提供；心跳占位值不作为性能数据。业务转发计费统计可用。
- 本轮只验证功能正确性，未给出公网吞吐或性能提升结论。

## 验证与部署

执行方式、依赖、示例配置和可选 systemd 单元见 [Agent 文档](../node-agent/README.md)。独立验证器通过真实面板 API、一次性 MySQL、外部客户端命名空间与 TCP/UDP 目标检查结果，不调用被测引擎内部函数来判定转发是否成功。

2026-10-25 在隔离 Linux amd64 环境分别验证 `iptables-nft` 和 `iptables-legacy`，各 32 项通过，包含真实 GOST 二进制回归、三层账本、重复上报、已有连接暂停、重启恢复、失联到期和配置收敛。WSS/HTTPS 另有受信任测试证书下的协议测试，Go 竞态检测和前后端构建通过。

所有转发测试目标位于测试容器内的 `10.203.0.0/16` 虚拟网络，Docker 网络为 internal，未使用 qcloud 广州入口进行转发测试或公网压测。配额用例通过设置测试账本触发，不产生 GB 级实际传输。

源码同步不等于上线：线上面板镜像、数据库结构和节点引擎保持原部署，生产迁移、镜像替换和节点切换需作为后续单独操作。
