# 转发引擎 P1 实施与验收

基线 `32a2ebb`，范围为原清单 11–20、29。沿用当前分支；不部署生产，不执行生产数据库迁移，不经广州入口测试。

实施顺序：

1. 统一多监听、多目标、DNS/健康运行状态；实现同族 IPv4/IPv6 编译、动态地址及 DNS 排空，保留已有单 IPv4 快速路径。
2. 共用业务 token、账本和额度。双栈/多目标不能各复制完整 credit；先进路径使用同 netns 的共享 token quota gate，所有地址族与目标消耗同一额度。先验证原生内核原语与原有屏障/恢复协议，再开放能力。
3. 增加独立路由表/规则，只匹配本项目原方向流量；限速只管理明确拥有的 IFB/qdisc/classifier，保留外部路由与 qdisc。所有变更纳入恢复与卸载。
4. 真实指标与有界诊断、能力驱动表单、desired/applied 状态；Android/iOS 当前为网页容器，复用网页业务能力，并验证桥接/移动布局。
5. 请求头认证、短期会话轮换、日志脱敏、专用无特权网络进程与受限本地内核 helper。旧 GOST/旧 Agent 保持明确的兼容路径。
6. 冻结最终二进制，完成四组原生矩阵和长稳态/并发/故障验收，对照基线，记录 CPU、吞吐、分位数、丢包、暂停、计费及恢复边界，最后同步本地与 qcloud-sg 源码。

实现与证据逐项完成后再更新原 29 项状态；不会把只有解析器或编译输出的功能标成端到端已支持。
