# 原生转发诊断修复及界面精简

2026-11-02，源码 `a9ec7f7` 已部署到 Oracle 面板前后端，以及 qcloud、qhix 的统一 Agent。两节点仍实际使用原生 nftables。

## 原因和修复

- 隧道诊断继续发送旧 GOST 的 `TcpPing`，原生 Agent 不支持。原生隧道现在读取实时节点信息与最多 100 条规则状态，返回实际检查数量及是否截断；不再默认向 Google 等外部目标建立连接。旧独立 GOST 的诊断路径保留。
- 普通数字 IP 转发可以没有 `AdvancedOptions`，原回程诊断却直接读取嵌入其中的出口字段，导致空指针 panic。qcloud 的转发符合此条件，诊断会让 helper 崩溃并被 systemd 重启；本轮只读复现也触发过一次。现按零值出口策略处理，补充真实普通规则的回归测试。
- 旧浏览器页面把路由读取显示成“连接成功”，并渲染空延迟和丢包数据。现区分路由、规则状态、显式 TCP 连接三种结果，只有实际测量才显示时间。每次新打开转发诊断默认不探测；可选 TCP 测试不会从上一条规则沿用。
- 技术说明曾直接堆在表单和卡片上。现把高级转发配置、回程字段和检查范围默认折叠，去掉日常卡片的版本、解析代次、识别计数及冗长说明，保留实际生效状态及必要操作提示。

隧道“状态正常”与转发“路由正常”各自说明检查范围，不证明公网端到端连接或客户端回程可达。实际连接测试需要在高级诊断中明确选择；UDP 没有通用的无业务协议回声验证。
