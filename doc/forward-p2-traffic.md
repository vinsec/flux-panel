# P2 第一批：本机路径与源地址模式

2026-10-27，基于 `feat/forward-engine-iptables`。本批实现 21、22 的基础路径，不表示 21–27 全部完成。不执行生产部署、数据库迁移或广州入口测试。独立验证结果另见 `forward-p2-validation.md`。

## 配置与版本

沿用 P1 端点、DNS、双族、目标池、业务 token、额度与账本。新 `traffic` 配置使用 ForwardSpec **schema 4**，Agent `iptables-v5` 协商 protocol 1/2/3/4 和相关能力。普通 P1 规则保持 schema 3，旧 IPv4 规则保持兼容路径。包含 schema 4 的状态采用 **format 5**，旧 Agent 拒绝读取；回退须先维护结算和恢复旧格式配置，不能直接覆盖二进制。

```json
{
  "schemaVersion": 4,
  "id": "1_2_3",
  "revision": 1,
  "enabled": true,
  "listen": {"host": "10.0.1.1", "port": 18000},
  "targets": [{"endpoint": {"host": "10.0.2.2", "port": 19000}, "weight": 1}],
  "traffic": {
    "localOutput": true,
    "localTargets": false,
    "sourceMode": "preserve",
    "returnPathConfirmed": true
  }
}
```

- `localOutput` 默认 false；开启后本机程序可通过本机监听地址访问转发入口，独立 OUTPUT 绑定集合不改变其他规则的捕获范围。
- `localTargets` 默认 false；允许转发到本机网卡地址或受支持的回环目标。
- `sourceMode` 默认 `masquerade`。`preserve` 采用 DNAT-only，拒绝与显式 SNAT 源地址组合。
- `returnPathConfirmed` 是管理员确认目标回程经过本节点，**不是 Agent 已自动证明远端路由**。缺少确认时拒绝保留源地址，不做静默 SNAT 降级。

端点仍按同族转发，独立 IPv4/IPv6 路径共享同一业务账本和额度；不提供 NAT64。

## 数据路径与计费

外部入口继续走 PREROUTING → FORWARD → POSTROUTING。普通包使用现有哈希集合，首包 DNAT 使用固定深度 token 树，不增加随全局规则数量增长的逐包扫描。

本机发起的流量经 OUTPUT mangle 绑定、OUTPUT DNAT，再按实际去向传输。本机服务的请求通过 INPUT 受控，回包经过 OUTPUT。每条规则的本机来源/本机目标集合独立，开启另一条本机规则不会放开原来仅支持外部入口的规则。

**在 OUTPUT、非回环 INPUT 或 FORWARD 计费。** 本机到本机的包在 OUTPUT、反向 DNAT 改写源地址之前计费；随后经过 `INPUT -i lo` 时再次检查放行状态，但不重复增加计数。监听地址别名只进入放行集合，不产生新的计费键，沿用既有计数水位、确认和回收模型。

本机通配 UDP 服务会根据返回路由选择源地址。默认地址转换模式因此对本机目标使用显式 SNAT：物理入口在 NAT INPUT 处理，本机到本机在 NAT POSTROUTING 先建立映射；源地址选为实际本机目标地址，避免不同网卡地址/回环地址导致回包五元组不匹配。普通远端目标继续使用原 MASQUERADE 或指定源地址逻辑。INPUT 支持 SNAT 的接口依据见 [Netfilter 扩展手册](https://ipset.netfilter.org/iptables-extensions.man.html)，具体行为以本分支真实双后端测试为准。

限额业务仍共享一个原生 nft quota 对象。INPUT/OUTPUT/FORWARD 的事务门同时关闭；本机回环 INPUT 不重复消耗额度。新增本机 hook 只对相应方向的规则计量，并跳过尚未 DNAT 的包，避免全部目标不健康时消耗预留额度。默认规则仍能在健康恢复后使用未消耗的窗口。

暂停、到期、额度耗尽均覆盖既有 TCP/UDP；本机服务与不同监听/目标地址使用同一业务累计值，不另建用户或授权账本。

## 兼容与资源

未使用 P2 的规则不分配 TrafficPolicy 对象、不增加空 JSON 字段，也不创建、计算或交换 P2 绑定/放行集合。P2 集合按需初始化，历史已创建的自有集合在维护卸载时回收。监听绑定和本机回复放行数量有明确上限，超限在安装前拒绝，避免无界展开。

后端创建、更新、批量对账和前端能力表单均使用同一新契约。额度服务接受已知 v3/v4/v5 版本族，拒绝未知主版本；v5 的额度发放及三层账本已纳入真实面板测试。

## 第一批的历史限制

2026-10-28 后续实现已补本地平滑限速和固定绑定 UDP 源地址，当前约束见
[第二批说明](forward-p2-local-shaping.md)。以下保留第一批验收时的边界。

- **本机路径尚不能与平滑/共享带宽限制组合**，能力为 `localTrafficShaping=false`。初次配置时面板拒绝；已有本机规则后来被加入共享带宽组时，对账将新策略送到节点，由节点关闭该规则并报告 failed，避免保留旧的不限速配置。移除冲突限速后恢复，账本不重置。
- **本机 UDP 目标的源地址保留尚不支持**，能力为 `localUDPPreserveSource=false`。通配 UDP 服务无法保证按原目标地址回包；需选择地址转换或 TCP-only。远端目标的 IPv4/IPv6 TCP/UDP 源地址保留已实现。
- IPv4 回环目标配合外部监听、或回环监听转向远端，需要事先配置 `net.ipv4.conf.all.route_localnet=1`。Agent 只读检查，不自动改全局 sysctl。纯本机回环不需要此设置；优先使用已分配网卡地址。
- 外部 IPv6 入口转向 `::1` 暂不开放，能力为 `ipv6LoopbackIngress=false`；使用已分配 IPv6 目标。IPv6 回环监听转向远端也明确拒绝，使用网卡监听及可路由源地址。通配 OUTPUT 始终保留回环捕获，目标不健康时也不回退到其他本地监听进程；不满足路由条件的回环到远端路径失败关闭。
- 实际本机目标没有可选择的物理出口，拒绝复用远端 `egress` 配置；若需要服务回包策略，应独立定义方向和路由契约。
- 暂不更新正式发布资产或生产镜像；新版本安装/生产灰度仍随第 10 项处理。
