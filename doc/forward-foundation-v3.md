# 转发引擎第一批基础能力 v3

基线：`7ed1955`（ipset v2）。范围为实施清单 01–09、28；本批不部署生产、不启用产品级域名或 IPv6 转发。IPv6 的 ICMP 错误编译器在独立路由夹具验收，完整双栈入口、NAT 和业务接口仍属于第 12 项。

## 配额与计费语义

普通用户进入新模式前，面板先要求节点把所有普通用户转发切入持久化的 strict credit 策略，并得到确认。单条旧格式请求不能降级该策略。共享用户不能同时启用新预留模式和旧 GOST/旧 Agent 模式；需先暂停并结算再切换。已有纯旧模式用户保留原行为，管理员豁免模式沿用原有约定。

额度预留同时约束 user 与 user_tunnel，数据库用 READ COMMITTED 和确定顺序的行锁避免跨节点重复发放；请求游标和最近 64 个回复保证重试幂等。额度原始字节按本次 lease 固定的倍率/单双向系数保守换算为计费额度。计费策略变更在旧 lease 结束后生效，避免已预留额度按另一倍率消耗。

内核 credit 为目标 IP + token 的共享双向计数。计数先增加再比较固定上限；越过预算的整包不通过，也不进入业务计费计数。放行集合与 credit 分开：无限额路径保留两次哈希查找；有限额路径用 credit 本身作为有效成员，避免额外逐包分类集合。重发同一 lease generation 不重新加成员、不重置预算；增加额度的 generation 才在相关 token 的屏障内按实际已用量重新计算。

默认 lease 上限为每次 4 GiB、有效期 30 秒，可配置 `engine.lease.max-bytes`（128 字节至 4 GiB）和 `engine.lease.duration-millis`（1–60 秒）。实际发放受剩余额度与同批请求分配限制。有限额节点每秒采样，空闲用户仅在需要补充或续期时请求，首次额度在业务数据库提交后申请，避免创建事务与上报相互等待。额度不足时拒绝数据，不能靠新 lease 重新获得同一份剩余额度。

失联节点的过期额度只有在最终用量得到确认后才归还。主机重启、netns 重建或计数不可证明连续时，不猜测未用额度；旧预留保持隔离。运行中计数消失/回退会关闭数据屏障、记录 `.counter-loss`，需恢复或结算后继续。这提供保守的配额保护，不承诺主机突然掉电前未落盘的原始流量能够无损恢复；恢复报告给出最后持久化时间和原因。

ICMP 错误控制包不计入 TCP/UDP 业务字节；它们受关联连接、token、类型、长度、速率和启停控制。跨引擎原始计量口径仍不同，不能把 iptables 网络层字节当作 GOST 应用读写字节。

## 恢复、回收与变更影响

状态、日志和 ACK 在磁盘上保留；schema 升级不会清空累计账本。提交前退出恢复旧代，提交后退出完成新代。无法验证日志或恢复失败时保持关闭，不自动忽略损坏文件。

常规少量启停、更新和额度变更只短暂阻断相关 token；大量原子变更或启动恢复会短暂阻断本项目转发。既有连接不会因为普通暂停而被清理；明确改目标/删转发/维护迁移才定向清理 conntrack。维护迁移会停止业务，需要显式恢复，不声称跨引擎无损迁移。

回收同时要求面板确认累计值、确认旧计数条目、连接引用归零与保留期。原始聚合基线只扣除已回收的条目，其他正在转发的计数保持连续。当前自动保留期为 5 分钟，管理员回收入口保留至少 1 分钟。token 容量为 65,535，可安全复用；普通配置的本轮验收规模为 10,000 条。

## 安装与迁移

数据库脚本 `001-forward-engines.sql`、`002-engine-foundation.sql` 必须显式按顺序执行；不会随应用启动自动运行。先在独立数据库验证，再由部署计划决定生产变更。

构建离线包：

```sh
python3 node-agent/packaging/build-release.py --output /absolute/new-release-directory
```

要包含 GOST，额外传入 `--gost-amd64`、`--gost-arm64`、`--gost-proof`；证据必须匹配确切哈希并包含 WS/WSS 与初始配置上报通过结果。不能用不明上游资产替代。脚本只生成包，不发布 GitHub Release。

新面板安装入口使用 `node.release.base-url`、`node.release.manifest-sha256`、`node.release.installer-sha256`。缺少固定来源与校验值时明确提示使用离线包，不回退未经验证的下载。节点密钥写入权限 600 的配置，不作为进程参数。

```sh
bash /path/to/release/install.sh --engine iptables \
  --bundle /path/to/release --manifest-sha256 VERIFIED_MANIFEST_SHA256 \
  --config /protected/node-config.json
```

安装器先核对包和配置、检查内核，再停止本项目服务。已有版本在受保护目录备份。新二进制原子替换，维护迁移最终结算并暂停面板期望状态；启动失败回滚到已校验的旧二进制和连续账本。断电留下的维护意图用相同操作与备份目录重试，或 `--maintenance resume`。

节点运行不需要 Java。依赖为匹配的 iptables/save/restore、ipset、conntrack、nft、CA 与管理权限，IPv4 forwarding 需预先配置；安装器不静默改主机 sysctl。systemd 只保留网络管理/原始套接字/端口探测能力，配置只读，账本与运行目录可写，共享 xtables 锁使用独立 tmpfiles 配置，不能更换为不与其他防火墙工具协调的私有锁。

`--offline` 不省略最终结算：它保留关闭状态，直到受信任面板确认业务期望状态已暂停。卸载保留账本、配置和备份，避免丢失待结算记录。`--ready` 要求新控制连接和新上报回执，不能只以 systemd active 判定成功。
