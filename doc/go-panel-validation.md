# Go 面板实现与本地隔离验收

日期：2026-11-02。Java 对照基线为 `a08e3d8`，开发分支为 `feat/panel-go-native`。
**已完成保留功能实现与本地隔离验收：64/64 HTTP 映射、47 项 Go/race/数据库用例、23 项 API/迁移检查、92 项真实 VM 检查及 600 秒稳态均通过。未部署线上。**

## 实现范围

新增独立 `panel-go/` 模块，一个 Go 进程接替 Java 面板；保持现有 React 界面和 MySQL 业务表。
支持 GOST 与原生 nftables，规范引擎值为 `gost` / `kernel`。旧 `iptables` 只兼容旧原生 Agent 的协议名称，
不提供 iptables 转发实现、后端下拉框或运行时回退。实际发送控制命令的会话也必须声明 nftables。
Agent/GOST 的产品源码和冻结二进制没有修改。

64 个 Java HTTP 映射均有 Go 实现和成功路径检查；还覆盖 `/system-info`、加密控制、会话、计费、额度及任务。
逐项入口和约束见 `panel-go/contracts/java-baseline.json`；功能、实现和测试对应关系见 `feature-matrix.json`。
验证码保留 SLIDER / ROTATE / CONCAT / WORD_IMAGE_CLICK 和原 TAC 交互。
前端只修正 JWT 的 base64url/UTF-8 解码，以兼容中文及特殊字符用户名，没有重做页面。

代码按 HTTP/鉴权、管理业务、控制、规格、存储、账本、额度和任务划分文件，仍是单体；没有引入 Redis、队列或微服务。
`006-go-panel-runtime.sql` 只增加任务完成记录和待完成批次表，须显式执行；不在启动时执行迁移，不重置已有账本。

## 性能方法和限制

Java 与 Go 各用独立、内容相同的测试库，同为 1 CPU / 384MiB；Java `-Xmx192m`，Go `GOMEMLIMIT=192MiB`。
在 3 / 1000 / 10000 条规则下，四类 API 各测三轮交错顺序，并先核对返回数据一致。
记录每轮 p50/p95/p99、响应字节量和进程资源；只比较面板控制 API，不冒充转发吞吐压测。
首轮 Go 的 1k 列表存在慢读数，结果保留。预计算列映射并使用与 Java DTO 一致的固定读取结构后重新测量。
最终数字、原始候选标识和不利读数以 JSON 记录为准，不以有利复测覆盖旧记录。
这台机器、该负载的观察不能推定所有硬件、公网、真实 NIC 或全部并发组合性能。
Linux AMD64 只完成交叉编译，不声称已经运行验证。

## 保留的协议边界

GOST 仍使用原 delta 上报，没有 report ID；本次没有给旧二进制凭空增加任意重试去重或内核式额度预留。
同一份正常 GOST 上报只处理一次，不把写请求同时发给两套面板；不能用时间/内容猜测去重，以免吞掉相同但合法的流量。
原生累计/租约模式承担严格的去重和共享预留约束。同一额度用户不能同时混用旧模式与预留模式。
普通无法识别流量继续放行并标 UNKNOWN。

新 Go 对异常输入更明确：服务身份必须为规范数字格式，不能用前导零制造不同水位键；计数和比特率不能被小数截断。
有效 API 路径、字段、鉴权/密码记录、正常错误及计费取整沿用基线。GOST 限速保留 Java HALF_UP 的一位小数口径。
管理级联删除保留旧行为：节点失联时可删本地关联，回连清理孤儿；显式强制删除不能声称获得了远端最终结算证明。

## 未来发布和回滚

本次没有上线。未来先核对当时的生产版本、备份和节点能力，再单独审查发布窗口。
首发整体交接：先停管理变更，等在途账本事务完成，停用 Java 任务和自动重启，再让 Go 接手。
Go 的单实例锁不代表 Java 也遵守该锁；不支持 Java/Go 共库混跑或自动多主切换。
交接应避开小时统计及午夜重置窗口，并明确旧任务是否已执行，不能让两边各重置一次。

回滚到配套 `a08e3d8` Java 时，先排空并停止 Go，再重连 Agent、核对最新累计水位与余额。
006 新表可保留，正常 Java/Go 回滚不执行 005 的引擎反迁移。
保留最新合法数据库，不恢复旧快照覆盖切换后的账单。数据恢复属于另一个明确损失窗口的操作。
GOST→nftables 节点迁移另行安排，不与语言替换合并，不承诺既有 TCP 跨引擎无损迁移。

## 最终实测摘要

真实 VM 10k 冷应用 3.87 秒，删除 9998 条孤儿规则 4.10 秒，存活转发和额度续期保持。稳态记录 197 组采样，累计账本单调，无确认失败。

性能候选在 12 组响应合同中与 Java 一致；最终控制 API 矩阵各组中位 p95 均未高于 Java。此前的不利候选结果仍保留，不能把这些虚拟环境读数解释为公网或所有工作负载保证。

完整机器可读结果见 [JSON](go-panel-validation.json)，逐项功能实现和测试映射见 [功能矩阵](../panel-go/contracts/feature-matrix.json)。

## 验证中修复的问题及环境说明

实际回归修复了：GOST 限速 HALF_UP 取整、含特殊字符的 Java 回滚重放哈希、中文/base64url JWT 解码、旧连接关闭覆盖新在线状态、取消请求泄漏 MySQL 命名锁、授权撤销与创建竞争，以及 GOST 部分失败后的补偿和额度执法。最终测试均在这些修复后重新执行。

早期 VM 轮次的节点重连等待、私网返回路由和 DNS 夹具问题已修正；误选旧 GOST 二进制的轮次不计入最终通过记录。一次测试 MySQL 被容器 OOM 杀死，经实际 OOMKilled 状态确认后，将该临时数据库内存上限提高至 1536MiB，再完整重跑；这不构成对 512MiB 数据库容量的验证。最终 600 秒通过结果不能推定全天或生产容量。此前失败日志仍保留在本地证据目录。

主要验证入口为 `go test -race -count=1 ./...`、`go vet ./...`、`tests/browser-flows.cjs`、`TestUnchangedGostWSSControlAndActualTCPUDP`、`node-agent/tests/node_backend_integration.py` 和 `integration.py`。后者实际使用 Go 二进制，并开启 SCALE、EXTENDED、ADVANCED 和 600 秒 SOAK；默认 Java 验证入口保留。数据库与浏览器环境参数必须指向一次性本地夹具，不能指向真实业务。
